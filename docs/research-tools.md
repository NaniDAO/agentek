# Compact explorer research (schemaVersion 1)

`getAddressTokenTransfers`, `getTokenTransfers`, and `getAddressNFTCollections` now return compact structured pages. History is distinct from current ownership. Required network identity is `{namespace: "eip155", chainId: decimalString}`. Unclassifiable filtered records remain in `unclassifiedItems`/`uncertainEvents`, including their usable transaction and block evidence. Nullable evidence stays null and contributes to `unknownRecords`; no decorative address tags, images, metadata blobs, market rates or embedded SVGs are returned.

Transfer records preserve sender, recipient, collection/token contract, standard, exact decimal-string token ID and quantity, transaction hash, log index, batch index when supplied, block number/hash and timestamp. ERC721 quantity is the standard-defined one unit. Unsafe numeric integers are unknown rather than rounded. ERC1155 rows without batch identity are not deduplicated because distinct batch events may otherwise merge. Identified events use block hash + transaction hash + log index + batch index + contract + token ID. Cross-page overlap remains inspectable in page reads; the recipient research tool deduplicates identified events across its bounded scan. Clients accumulating separate scans must use that identity themselves.

Pages support exact collection filtering and incoming/outgoing/both address filtering. Filtering occurs after reading a complete upstream page, so a page with no matches does not establish empty history. `coverage` exposes scanned record counts, block numbers, explicit oldest/newest scanned block range with `snapshotPinned: false`, removed duplicates, unknown records, endpoint exhaustion and completeness. A terminal page is not proof that earlier pages were read. Ownership preserves collection quantities and provided token instances but explicitly does not assert that the upstream instance previews are exhaustive.

`continuation` is an opaque bounded string, tied to network/address/kind/filters. It echoes returned `next_page_params` rather than inventing numeric pages. When a local output limit interrupts an upstream page, continuation replays that page at an explicit offset and verifies a hash of its compact records before proceeding. Changed pages fail with `page_changed`; callers should restart and deduplicate accumulated evidence. Numeric page/offset support was removed from getTokenTransfers because its previous implementation had no supporting evidence. Missing, malformed or repeated next-page parameters do not mean exhaustion. Explicit null marks endpoint exhaustion. No serialized JSON is sliced; oversized records/pages fail explicitly. Page size is 1–20 complete records, default 10.

`getNFTTransferRecipients` scans at most five ten-record pages for an exact outgoing sender/collection. It returns observed recipients and original event evidence. `allRecipientsEstablished` is true only for a scan starting at the beginning, reaching explicit endpoint exhaustion without unknown records or failed reads. This means supported explorer-indexed history, not independent proof of all chain history. A continuation scan cannot assert the earlier scan was read or had no missing evidence. Failures after successful pages retain their events and a structured error with `partialResult: true`.

## Evidence limits

The pre-existing researchCA offline fixtures already used `next_page_params` objects and explicit null. New synthetic fixtures exercise exact echo behavior, multiple pages and replay. No captured upstream responses with their final pagination fields were supplied; the conversation exports are cut off before those fields. These tests establish the implementation's contract against the supplied fixture protocol, not live upstream behavior. Do not represent invented synthetic pagination fields as independently verified live API semantics. A captured, sanitized upstream multi-page response or separately authorized API verification is still needed to settle that external contract. No live requests were made.

The SmartContracts code has no name-specific branch. HTTP, transport, malformed JSON and timeout failures reproduce offline. The observed native failure occurred about 32 seconds after the call; NANI's old native 30-second rejecting timer raced the explorer's 30-second abort timeout. That rejected promise bypassed __naniCall's error envelope, a reproducible mechanism for the generic JavaScript boundary failure. The export has no underlying exception or response: the exact cause of this particular occurrence remains unproven.

The shared bridge retains a backward-compatible error string and adds safe `errorInfo`: schemaVersion, operation, category, retryable, partialResult, outcome and a fixed message. Arbitrary upstream bodies, exception strings and credentials are not returned. Unknown action failures have unknown outcomes and are not retryable. Reads classified by the explorer adapter expose HTTP/transport/timeout/malformed-response categories; no automatic retries are added. Subsequent reads remain usable.

## Native handoff

NANI must remove successful-result prefix slicing, validate complete research envelopes and preserve structured failures/partial evidence in transcript and recovery. Its outer timeout must resolve a structured failure instead of rejecting an unhandled JavaScript exception and must exceed the shared timeout. Search is owned partly by NANI: its 5:1 name/description word ranking promoted construction tools for transfer research; metadata alone cannot correct that weighting. Prefer historical reads for ordinary recipient/history tasks while retaining relevant construction tools and exact-name discovery. NANI's coordinated changes implement these items; Xcode/WebKit execution requires an Apple host.

The hosted-model request failure is assigned to the NANI hosted API/server investigation, using support reference 93842991-FA43-4F29-B50A-0C854DCAD066 and server request logs. No server evidence was available, and this work does not claim to fix that failure or prove causation from the JavaScript read error.
